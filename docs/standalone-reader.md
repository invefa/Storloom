# Independent HTML reading

Version 2.10 reads a v3 compact reading archive directly in a desktop browser, without Storloom, a server, network access or unpacking all media. The HTML is an entry point, not a self-contained copy of the chat content. Keep the entire archive directory when moving it.

Enable independent HTML reading under task details in the creation form, or select Independent HTML reading on an existing compact account. Open `index.html`, choose the archive directory and grant read-only access. New reading archives in 2.11 put their internal files inside `archive-data`, beside `index.html`. Both the outer directory and the data directory can be selected; existing flat archives remain supported. Move the whole directory together. Browser permission requires a user gesture. Compatible directory selection enumerates files first and can take longer on large directories. Cancelling selection is harmless.

Password envelopes and direct keys use the existing archive credentials. Password changes do not require rewriting content or regenerating HTML. Credentials and decrypted content are not persisted in a browser database. Appearance preferences use local storage when available. Lock / close terminates the Worker, clears the view and releases object URLs. JavaScript cannot guarantee physical erasure of every secret copy.

With Remember this archive directory enabled, supported browsers retain only the directory handle and archive identity in IndexedDB. An existing read grant restores the directory on reopening; protected archives still require their password or direct key. If permission expires, Continue opening requests read-only access from that click. Startup never opens an authorization prompt. Forget directory removes the stored handle; unchecking memory also removes it and retains the opt-out when local storage is available. Each HTML location has its own record, including copies of the same archive. Lock closes the reader without immediately reopening it. A replaced archive is rejected until explicitly selected. Browser policy, private mode, cleared storage and local-file URL restrictions can prevent persistence; ordinary and compatible selection remain available, but compatible file lists cannot be remembered.

From 2.12, new bundled archives separate immutable data into `archive-data/packs/` and commit history into `archive-data/commits/`. The `query/` and `browser/` directories contain query indexes and browser snapshots. Small configuration, wrapped-key, current-head and task/lock files remain at the data root as control metadata. New readers accept both this layout and the original flat layout. Older readers require an update to read categorized archives. Existing archives can be organized with same-volume renames after closing their readers; the operation checks file identity and preserves the published snapshot, and an interrupted mixed layout can resume. When a filesystem such as exFAT changes file IDs on rename, the moved object's content digest is checked instead, adding one-time read I/O. Organizing files does not change encryption or split messages into more files.

The existing reader provides conversations, paging, search, references, identity information and image previews. Single media files over 32 MiB are not buffered for inline playback. The save action streams chunks with the file-save API; compatible Blob downloads are bounded to small files. Save a large file and open it in an external player. Browser codec limitations still apply.

A read-only WASM VFS uses File.slice and FileReaderSync in a Worker against the existing query database. It does not load the full index into memory, copy it to OPFS or build duplicate search postings. Page and Blob caches have bounded budgets. Runtime components are embedded in one HTML. Small conversation summaries live in the existing index, and the protected snapshot manifest contains the reader metadata.

First preparation of an older archive aggregates conversation summaries from its index. New archives maintain these summaries incrementally from their first commit, including when HTML reading is enabled later. Native backups must first be parsed into reading archives.

The desktop reader performs archive resources, searches and saved-resource reads in background work, serializes access to its query connection, lazily loads images and retains at most 16 MiB of small-resource responses. Media responses read at most 4 MiB per range, so a slow disk does not leave a deferred archive stream on the UI thread. This improves responsiveness; it does not remove the physical disk's throughput limits. QQ contact/group avatars can be downloaded with the optional Tencent avatar setting. WeChat avatars are read from supported local avatar databases. Unavailable images retain their fallback, and supplemented avatars do not replace recorded identity history.

Browser roots match a published HEAD and its archive-local query snapshot. Updates prepare a candidate before publishing HEAD; interruption preserves the existing reader. A detected snapshot change requires refresh. Compatible file selection captures File objects which may become stale after updates; select the directory again. Copying retains an available browser snapshot and index; reorganization and protection conversion prepare a corresponding entry for the destination. Missing old projections require explicit entry regeneration instead of a silent full history scan in the browser.

The CSP blocks network connections and remote media. Archive scripts are parsed as data, not executed. Local file tests on the installed independent Edge cover plain/password/direct protection, wrong credentials, paging, search, references, images, large-media bounds, locking and snapshot changes. No security switches or extra launch flags are required. Chrome uses the same APIs but was not installed for local verification; other browsers are not guaranteed. Directory authorization can be restricted by browser policy, in which case use compatible selection.

Common terms, late pages and slow disks can require more index work. Queries have a deadline and report failure. Small-fixture timings are not a promise for every operation on million-message archives.

The unlock screen and reader share appearance choices across reading archives in the same browser. Brightness and palette changes carry back to the unlock screen after locking; passwords and message data are never part of these preferences. Page/navigation settings remain scoped to each archive.

Opening an existing desktop archive can reuse its matching authenticated browser metadata snapshot instead of reopening metadata chunks in data packs. Timeline pages use the nearer end of the index when conversation summaries are available. The HTML reader prepares its codecs during password entry, uses bounded 16 KiB index read-ahead, and coalesces simultaneous requests for the same avatar/resource. Existing archives retain their format; refresh the independent HTML entry to obtain the browser changes. Disk seek latency and very large searches can still dominate.

Quotes show the original sender and time when the message is present in the archive; embedded WeChat quote timestamps are also retained. Visible quotes resolve metadata on demand, without ranking every quoted message or loading all conversation pages. Reference lookups cover the archive index, and QQ lookups can fall back between message IDs and sequence IDs within the same conversation. A lookup error is shown separately from a missing original; a missing original means it was not found in this archive, not proof that the client deleted it. Search/filter conditions remain visible in the header with a clear action while the panel is collapsed; running searches have a separate busy state. The page-size entry and SVG preset toggle share one focus border.

QQ quote recovery also reads the sequence, sender and time carried in the original wire payload, including older reading copies whose parsed quote fields are empty. Alternative recorded sequences are checked against the quoted sender/time before navigation; conflicting records are reported instead of opening an unrelated message. Unrecorded sender/time fields are omitted. Existing copies only need an updated reader entry, without rewriting chat messages.
