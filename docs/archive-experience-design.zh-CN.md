# 归档使用体验设计

## 目标

一份归档应当在离开原机器、原目录、原软件配置后仍能被识别和阅读。元数据说明它是什么、来自哪里、经历了什么；本机配置只负责当前资料列表和操作偏好。账号归组、归档副本和原客户端来源是不同概念。

## 场景与本次实现

| 用户场景 | 需求 | 实现与边界 |
| --- | --- | --- |
| 换电脑或程序配置丢失 | 找回已有资料，不重新导出 | 选择 `archive.metadata` 接入；新增“扫描找回资料”，扫描后勾选确认，恢复账号分组与已保存的来源历史 |
| 一个备份根目录有多层文件夹 | 不猜正确的目录层级 | 单份归档选元数据；批量恢复选上层目录，发现归档即停止进入其内部数据目录 |
| 归档搬家、盘符变化 | 更新路径，保留身份 | 读取相对数据位置；重新接入会修复同一标识且旧位置已失效的登记；项目匹配还要求原来源标识、平台和账号一致 |
| 两个真实副本同时存在 | 不把副本误当成移动 | 仍可作为不同位置保留；不覆盖可用旧位置，不删除文件 |
| 多份资料属于同一账号 | 明确资料与账号的关系 | 按平台、账号分组；未知身份保持独立，可手动关联 |
| 忘记归档来源或转换经历 | 可追溯原始客户端和直接父归档 | `origin` 保存原始来源；`history` 继承并追加导出、复制、转换、整理等事件；历史页展示 |
| 老归档缺日志 | 区分已知事实与补登记 | 恢复事件单独标记；修复时间不冒充导出时间，未知旧软件版本留空 |
| 新旧版本交叉使用 | 避免误解格式或破坏归档 | 分别记录元数据结构、导出协议、内部存储格式和导出软件版本；拒绝未知协议，保留原文件；兼容旧元数据文件名 |
| 加密归档仅需恢复资料列表 | 不反复要求密码 | 外层元数据可读取；恢复登记不解密聊天，实际阅读继续要求原密码 |
| 未完成、损坏或离线的归档 | 扫描不能假装全部成功 | 展示跳过项及原因；目录数和深度到限时明确标为部分结果；逐项接入失败不撤销已成功登记 |
| 整理资料列表 | 删除登记与删除数据要分清 | 右键移除仅修改本机目录；打开归档位置可核对实际文件；不隐式清理数据 |

## 数据约定

`archive.metadata` 与独立阅读入口 `index.html` 并列。内容为 JSON，数据路径只允许当前目录或 `archive-data`，不能将程序引向归档外的任意数据目录。公开的来源路径仅用于描述，不自动作为更新、还原或删除操作的授权。

元数据结构版本当前为 2，导出协议为 1。协议版本与软件补丁版本无关，只有导出语义发生兼容性变化才提升。旧兼容导出管线按协议 1 识别，原软件版本不明时不推测。操作历史采用事件标识去重，中断重试同一版本不会反复追加。它是可携带的来源记录，不是防篡改审计签名。

扫描只读标记文件，不解析消息包、生成索引或获取密钥；不跟随链接，限制扫描深度与目录数量。确认后才写元数据或本机登记。默认不从目录名称猜账号，不从公开来源字段擅自创建可执行的还原任务。

## 后续优先级

| 优先级 | 功能缺口 | 设计方向 |
| --- | --- | --- |
| P1 | 本机完整配置仍需要单独备份 | 提供显式导入/导出配置包，区分资料登记、偏好和密钥库；敏感内容默认不包含，包含时加密并单独确认 |
| P1 | 多个有效旧版本之间缺少差异概览 | 比较消息/资源数量、时间范围和缺失资源，先复用现有索引；不为打开列表而全盘解密扫描 |
| P1 | 完整性状态缺少统一入口 | 汇总已有验证能力，记录验证时间、范围和结果；明确“元数据可读”不等于“所有消息和媒体已验证” |
| P2 | 原件备份的批量发现尚未覆盖 | 在同一恢复预览中分类型展示，接入时沿用原件清单验证与解锁流程；不能当成普通阅览版登记 |
| P2 | 多归档任务需要更好的统一排队 | 每项保留配置、进度和失败原因，支持继续与取消；完成后原位展示结果 |
| P2 | 长期保存需要更强来源可信度 | 设计可选的清单签名和离线验证，不把公开、可编辑元数据误称为可信证据 |

本次优先补齐自描述、可找回、可迁移和可追溯。配置包、版本对比、原件批量接入与签名仍是后续设计，尚未实现。
