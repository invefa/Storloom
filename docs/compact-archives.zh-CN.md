# 紧凑归档

2.7 新添加的账号默认推荐紧凑存储. 在建立阅览版或原件备份的设置中选择格式. 2.8 修正遗漏的新建入口默认值; 没有未完成任务时, 原件备份也可选择下一次备份的格式, 另建紧凑备份而保留已有普通备份. 已有资料保持原格式, 不会自动转换或删除.

- **紧凑归档 (推荐)**: 将小资源合并到数据包, 消息直接写入持久化索引. 在程序中打开, 无需先解压全部内容.
- **普通文件夹**: 保留独立媒体文件及静态 HTML. 需要静态 HTML 或精细选择加密范围时选择此项.

## 阅览版与原件备份

二者独立建立和更新. 建立阅览版不要求先备份原件. 原件备份不需要数据库密钥, 用于还原原来的文件结构; 建立阅览版仍需要正确的数据库访问凭据.

紧凑阅览版更新时跳过未变化的数据库, 对变化的数据库重新解析, 复用已有消息及资源, 仅提交有变化的记录. 这不是所有客户端都支持的逐行数据库增量读取. 仍会读取数据库以确定变化, 并扫描相关资源目录. 有缺失资源时会重试解析以补齐资源.

原件备份保留历史快照, 相同资源块在同一个归档内复用. 快照清单按路径散列分片, 小范围变化不要求重新保存整份清单. 在原件备份页选择还原时可选择历史快照. 程序还原并校验到新的目录, 不覆盖正在使用的客户端资料. 实际导入客户端前仍需检查版本和还原结果.

从紧凑原件备份建立阅览版, 目前需要先临时还原一份完整原件用于解析, 因而需要额外空间. 受保护备份的临时目录使用 EFS. 成功建立后清除该临时副本; 中断时保留以便继续.

## 密码与中断

紧凑归档采用随机数据密钥, 密码只用于保护密钥封套. 修改密码无需重新加密所有内容. 资源记录使用 AES-256-GCM 独立认证, 查询数据库也加密, 密码至少 8 个字符. 密码不会自动保存, 请自行妥善保管.

更新遵循已有归档的保护状态. 新增和变化的内容与已有内容保持相同保护方式. 通过账号页单独执行加密或解密转换, 完成后才切换到新副本, 原归档保留. 紧凑归档也支持直接密钥模式, 输入 64 个十六进制字符 (256 位). 此模式不使用密码封套或 PBKDF2, 不保存密钥, 打开索引前先验证密钥. 直接密钥无法通过修改密码来替换, 更换需要重新加密内容. 更新, 续传, 备份副本和整理沿用已有归档的密钥模式. 部分加密仍使用普通文件夹格式.

暂停会在安全检查点等待, 仍可取消. 继续任务时需要相同来源和必要凭据. 来源数据库变化时会拒绝拼接不一致的任务. 可明确放弃任务再开始, 已发布的快照保持可读. 未完成的私有数据包会保留, 可以在之后整理到新副本时排除.

受保护阅览版解析期间会生成 EFS 保护的临时数据库和消息暂存文件, 因而工作磁盘需支持 EFS. 紧凑原件备份直接打包原件, 不依赖 EFS.

已有普通文件夹可在高级存储选项中选择从本地另建紧凑阅览版. 这会读取当前本地来源, 保留原阅览版, 不会自动合并仅存在于旧阅览版的历史消息. 若要将旧阅览内容完整保留在紧凑格式, 使用导入阅览版入口; 该导入归档仍通过导入已完成阅览版来更新.

## 查阅, 导出与整理

在账号的阅览版页直接打开或更新. 紧凑格式的读取只解码需要的资源块. 导出 HTML 阅览版会生成独立文件夹, 可用于浏览器或旧版程序; 导出时仍可选择密码保护.

高级存储选项提供存储统计和整理到新副本. 统计区分消息数, 逻辑条目, 数据包, 查询缓存和其他元数据. 文件长度不等于文件系统实际分配空间, 也不包含全部文件系统元数据开销.

整理会流式复制当前消息和保留的原件快照, 排除未引用数据和消息修订历史, 原归档不删除. 未被读者使用的旧查询缓存会自动回收, 正在打开的阅览版保留自己的查询快照. 查询缓存可从包重建; 新格式重建索引时不需要读取全部媒体正文.

独立校验仍可从账号的原件备份页执行. 普通打开和增量更新不会顺带全量校验全部历史数据包.

## 兼容性和性能边界

新版继续读取普通阅览版及旧版打包归档. 新紧凑格式需要 2.7 或更新版本; 旧版程序和浏览器请使用导出的 HTML 阅览版. 不要手动删除归档内部的数据包或清单.

紧凑格式减少独立小文件数量, 不保证搜索索引比原文本更小. 索引和历史仍占空间. 为使更新中断时旧版保持可读, 更新需要准备一份查询索引快照, 这是索引文件的顺序复制, 不是重新解析所有历史消息. 工作空间需能容纳当前索引及更新中的副本. 线程自动推荐依据硬盘, CPU 和内存情况选择, 也可手动选择 1-32. 增加线程不保证更快.

## 账号与来源别名

账号页的数据来源标题右侧提供别名编辑入口. 同一平台与账号的多个来源共享账号别名, 各来源单独保存来源别名. 原始账号和来源路径仍可核对, 不修改目录, 数据库密钥, 归档标识或消息内的联系人名称. 别名只保存在本机管理设置中, 不写入聊天归档. 留空可恢复原显示名称. 密钥库的账号选择也显示这些别名.

## 2.9 的工作目录与任务反馈

在首选项的任务页设置工作目录, 或在开始前展开任务说明调整. 输出在机械盘时建议将工作目录放到 SSD. 留空沿用输出位置. 程序在 `Storloom/<来源标识>` 下分类创建任务目录. 工作目录用于数据库和消息暂存及紧凑格式的私有查询索引, 原始来源和最终数据包仍位于各自磁盘. 受保护明文暂存仍要求支持 EFS. 完成时把查询索引复制并验证到输出目录, 清理临时工作后归档仍可独立读取. 请预留工作索引及最终副本的空间.

中断任务会沿用原工作目录, 修改首选项不会搬迁未完成工作. 请使用同一来源快照和凭据继续; 新设置用于新任务. 成功后尽量清理任务派生文件, 无法完成清理时会记录保留工作目录的提示.

紧凑写入索引使用 WAL, 受保护索引的 WAL 也加密, 保留完整同步写入并使用有上限的页缓存. 新索引减少无效的缺失记录查找, 分词与正文准备可以并行, 数据库发布仍按顺序进行. 日志分别统计累计打包准备, 数据包持久写入和索引应用耗时. 索引耗时包含数据库计算与存储等待, 不等于纯 I/O 时间. 最终索引复制与来源解析还会额外耗时, 可据此判断主要时间花在存储还是打包加密.

暂停在安全检查点等待, 保持任务打开. 停止任务会立即显示已收到请求, 禁止重复停止, 并在当前步骤退出或回滚期间显示不定进度条. 每 5 秒记录等待时长, 直到后台真正结束. 已完成步骤和可用检查点保留, 是否能续传取决于任务类型. 回滚期间不显示虚构的百分比. 必填信息不完整时不能开始, 从表单返回会保留来源和本次窗口内的草稿. 草稿凭据只驻留内存, 关闭窗口时清理.
