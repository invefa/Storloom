# AI规则指南

Storloom只接受描述数据的JSON规则，不包含AI账号、API密钥、提示词执行或云端上传功能。可以把下面的提示词交给自行选择的AI，仅提供愿意披露的路径和文件元数据，将生成的JSON保存在本地。

## 可复制的提示词

请根据随附的rules.schema.json和rules.zh-CN.md，为Storloom生成version=1的严格JSON规则目录，只返回JSON，不要附加Markdown代码围栏、命令或脚本。

来源、目标或操作意图不明确时先询问，不要猜测有破坏性的路径。使用稳定的小写标识符、明确根目录、相对include与exclude模式、清晰名称与说明，并设置risk为Review。可以在names和descriptions中提供en与zh-CN翻译。

归档默认使用Copy。只有我明确要求、已有依据确认可以重建的缓存或日志才可以Delete。不要把聊天数据库、账号、凭据、文档、源码、仍在使用的安装文件或系统组件当作缓存。

优先使用支持的路径变量。不要把整个磁盘、用户目录、AppData或软件安装目录作为删除根目录。遵守保留时间、进程限制和排除条件，进程名称不带.exe。Copy与Move的目标必须是新的、与来源互不嵌套的目录。使用%BackupRoot%前说明需要本地settings.json配置。目标中的{RootName}可代表匹配根目录的末级名称，应避免多个来源映射到同一目标。

匹配模式只选择文件，按规则归档不能代替完整账号备份。不要把秘密、机器标识、账号号码或私人事实写入规则标识与说明。

我的需求和目录：
[填写来源、清理或归档范围、必须保留的内容、时间与大小限制、Copy或Move或Delete意图，以及用户选择的目标目录。]

## 审核流程

1. 在编辑器中用[规则结构定义](../rules/rules.schema.json)校验输出。
2. 使用“文件 -> 导入规则”。导入按标识合并到本地覆盖配置，不删除启用的内置规则集。
3. 扫描并检查路径、动作、保留时间、进程限制、诊断和归档目标。不确定的内容取消勾选。
4. 审核具体计划后确认执行。记录与备份清单应保密，配置改变或计划过期后重新扫描。

AI输出不构成删除授权，界面确认和引擎检查始终生效。运行时保护也无法判断某个私人文件对用户是否重要。无需向AI发送聊天正文或密钥。

## 使用原软件清理

需要产生数据的软件自行清理缓存时，使用action为Command、risk为Review、roots为空数组，并选择已支持的tool：NuGetHttpCache、NpmCache、PipCache或UvPrune。

说明操作会覆盖工具配置的整个缓存，并说明uv清理可能移除共享项目环境。不要编造可执行文件、脚本或参数字段，不要嵌入Shell命令。固定命令由应用维护，用户确认实际解析出的程序与参数。超出支持列表的工具需要另行审核并实现适配，不能将任意代码伪装为清理规则。
