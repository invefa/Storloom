# 归档库

2.7 新账号默认推荐直接建立紧凑归档. 格式选择, 原件快照, 保护及整理请参见[紧凑归档](compact-archives.zh-CN.md). 下列导入方式继续用于已有阅览版.

在 **聊天归档 > 工具 > 存储维护** 管理新的打包存储格式. 已有备份和阅览版仍可通过原有入口使用. 程序不会自动迁移数据.

## 接入文件与恢复资料登记

点击 **聊天归档 → 接入已有资料**，直接选择归档文件，不需要判断应选哪层目录：

- 新阅览版、紧凑原件备份，以及导入、复制、整理得到的紧凑副本，在外层提供 `archive.metadata`。准备过独立 HTML 时，旁边还有 `index.html`；内部数据仍保存在 `archive-data`。
- 旧紧凑归档可选择内部的 `archive.json`，也可选择外层 `index.html`。程序会将 `archive-data` 归一到外层归档，并避免重复登记。
- 旧文件夹阅览版可选择 `messages.html` 或 `vault.storloom.json`；普通原件目录备份继续选择原来的备份清单 JSON。

已有元数据中的客户端、账号会自动用于归组。旧阅览版缺少这些信息时，接入窗口允许填写 QQ 号或微信账号目录标识（如 wxid），也可留空保留独立资料。已有独立资料可在左侧右键选择 **关联账号**。保存会补写外层元数据，不重新导出、不重新加密，也不需要阅览密码；实际阅读仍使用原有密码。

元数据保存归档标识、类型、客户端、账号、相对数据位置，以及原始来源和操作历史；不保存密码、密钥、聊天内容或完整本机任务配置。来源可能含原客户端的绝对路径，属于公开描述信息，不作为还原或更新的授权依据。归档移动后仍按相对位置读取，不依赖旧来源路径。账号关联不会把阅览版变成原始客户端数据，更新仍需接入真实客户端来源或原件备份。

左侧称为 **归档资料**：已知平台和账号的来源按账号归组，未关联的阅览版仍单独显示，不再将内部文件夹名称视为账号。右键可编辑分组/来源别名、移除当前来源或整组登记。**从列表移除只删除本机登记，不删除磁盘上的归档、备份和阅览内容。** 有未完成任务时，先完成或放弃任务再移除。

重新接入可以恢复资料列表和账号归属。多份历史阅览版、原件备份仍在时，可分别接入；资料历史会显示已登记的版本。仅凭阅览版不能原样恢复已丢失的完整任务日志、导出设置或数据库密钥库；这些需要原来的本机数据目录备份。


## 批量找回与归档移动

“扫描找回资料”允许选择备份根目录，只读查找兼容且完成的阅览资料，勾选预览后恢复登记。跳过项和扫描上限会单独显示；原件备份仍通过“接入已有资料”验证接入。归档移动后重新接入元数据，可修复匹配且旧路径已失效的登记；仍可访问的真实副本会保留。更多场景与后续设计见[归档体验设计](archive-experience-design.zh-CN.md)。

## 协议与来源历史

`archive.metadata` 与 `index.html` 并列，内容仍为 JSON。`version` 是元数据结构版本（当前 2），`exportProtocolVersion` 是独立的 Storloom 导出协议版本（当前 1），`storageFormatVersion` 是内部存储格式版本，`exporterVersion` 是实际导出/转换的软件版本，四者各有用途。导出协议 1 对应现有导出管线和兼容阅览版；遇到未知协议或结构版本会停止接入，保留原文件。

`origin` 描述原始客户端来源，`history` 记录导出、原件备份、导入、复制、整理、解密等事件及其直接来源。复制或转换会继承历史并追加事件，相同版本的中断重试不会重复追加。历史在程序的资料历史页可见。旧 `archive.storloom.json` 仍可选择，保存时校验后迁移为新名称。

补登记旧归档时，能核实的来源才写入，记录标为 `recovered`；记录时间是本次修复时间，原导出软件版本未知时留空，不推测原始导出日期或伪造完整任务日志。即使程序配置丢失，重新选择元数据仍能恢复账号归属、来源说明和已保存的操作历史。

## 导入与更新

选择 **导入阅览版**, 指定已完成的阅览版和新的归档库目录, 核对来源与目标后开始. 来源保持不变. 中断后选择相同来源和归档库目录即可继续. 未完成的导入不接受变动后的来源.

后续通过 **更新 / 继续导入** 选择同一账号更新后的完整阅览版. 程序扫描来源消息以发现变化, 未变化消息不重新索引, 未变化资源文件复用已记录的文件身份. 此入口尚不直接从原始备份读取增量. 首次导入、查询缓存重建和来源扫描会分别展示进度, 不应理解为固定耗时的操作.

消息、搜索索引、资源位置和断点一起提交. 原始消息 JSON、未知字段和来源文件保存在不可变数据包中. 小文件合并打包, 大文件分块. 旧消息版本保留在历史提交中, 阅读器展示最新版本.

## 阅读、搜索与备份

选择归档并 **打开阅览版**. 内置阅读器直接加载当前页面和媒体, 无需先整体解包. 仅按文字进行的全局搜索使用持久索引; 同时使用其他筛选条件时保留兼容的分页查找路线. 引用跳转通过消息标识索引定位.

**增量备份** 选择新目录或此归档已有的备份目录. 只复制并校验新增提交和数据包, 最后发布新快照. 中断的备份先完成此前选定的快照, 再运行一次可收集此后变化. 不复制查询缓存, 首次打开备份时会重建缓存.

**立即校验备份** 独立执行全归档校验, 展示提交数和字节总量. 日常打开和更新不会自动读取所有历史数据包. 校验包含消息历史版本及资源块, 因此消息版本数量可能大于阅读器中的当前消息数.

## 密码与导出

创建归档时可选择加密. 加密来源阅览版必须导入加密目标. 私密数据包和查询索引均加密, 不自动保存密码. 密码至少 8 个字符. 修改归档密码只重新包装主密钥, 无需重写所有数据包. 旧备份在更新前继续使用旧密码. 这不能撤销已经泄露的主密钥副本.

新归档库目前支持整体加密. 精细范围保护仍可用于兼容导出的阅览版, 归档库内部混合公开域和私密域尚未启用.

**导出阅览版** 根据当前查询状态生成最新页面、引用表和 JSONL, 同时复用已保存媒体. 选择新目录, 或在来源归档发生变化前选择上次中断的导出目录. 续传会检查已完成文件与恢复记录是否一致, 拒绝无关目录及已被改动的文件.

导出窗口也可选择密码保护. 加密在导出完成后开始, 因此未完成的导出或加密可能在目标保留明文. 若加密中断, 请在 **工具 > 加密 / 继续加密阅览版** 选择目标目录, 输入导出密码继续. 归档库和原始来源保持不变. 明文阅览版可被任何能够访问磁盘的人阅读.

导入、备份、导出、加密和校验共用现有暂停和取消控件. 取消后保留已提交断点. 阅读窗口关闭后释放更新锁; 导入新内容或修改密码前请先关闭目标归档的阅读窗口.

## 当前边界

此版本的归档库迁移和备份采用串行基线. 既有备份、导出和加密任务的线程推荐不代表归档库迁移或备份已使用 8 个线程. 双硬盘、冷缓存、低内存和断电持久性测试仍待完成. 模拟测试覆盖进程内中断恢复; 单个存储设备仍不能代替独立备份.
