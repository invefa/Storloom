# 紧凑归档的独立 HTML 阅读提案

状态: 原始提案, 由 2.10 实现验证后调整. 实际方案直接以只读 WASM VFS 分段读取已有查询索引, 无需另建消息目录或搜索倒排. 当前使用方法和限制见 docs/standalone-reader.zh-CN.md. 下文保留最初方案供设计追溯, 不作为已实现行为的说明.

## 目标与入口

归档附带 `阅读.html` 和固定数量的离线脚本资源. 双击 HTML, 点击选择归档目录并授予只读权限, 必要时输入阅览密码或直接密钥, 随后阅读. 不安装或启动 Storloom, 不启动本机服务, 不联网, 不上传内容. 不要求解压所有资源, 不在浏览器配置目录复制整份归档.

沿用现有阅读界面, 包括联系人和群资料, 历史名称及头像, 分页, 引用跳转, 全局和会话搜索, 媒体预览及设置记忆. 原件备份与阅览版仍是不同用途的输出: 未解析的原件备份不能直接变成聊天页面. 本提案首先服务于紧凑阅览版.

独立读取作为紧凑格式的一项可选能力, 不强迫仅使用桌面阅读的用户承担额外索引生成成本. 新建和更新阅览版时可选择启用, 已有归档提供单独的生成或更新入口. 保留现有兼容文件夹导出.

## 浏览器可行性先行

首先做最小离线原型, 实测当前 Windows 桌面 Edge 和 Chrome 的 `file://` 场景. 验证目录选择, 文件分段读取, WebCrypto, Worker, 脚本加载和大文件视频. 不能仅凭存在某个 API 就宣布支持. 不要求用户关闭浏览器安全机制或修改启动参数.

优先使用只读目录句柄和 `File.slice()` 定位读取. 无目录选择 API 时试验目录输入控件或文件拖放; 如果必须枚举所有文件, 明确显示该兼容路径的准备成本. 权限需要用户手势, 不能承诺首次零点击或跨浏览器自动授权. 取消选择不报错, 权限被撤销可重新选择. 不支持的浏览器应清晰提示, 不暗中改为依赖桌面程序或服务器.

所有脚本与解码器本地打包, 不依赖 CDN. `file://` 下 Worker 和 WASM 的启动方式也必须验证; 可以使用内嵌或 Blob Worker, 不假定 HTTP 响应头或跨源隔离可用. 不将 OPFS 或 SharedArrayBuffer 作为必需条件.

## 存储: 共享正文, 增加浏览器目录

推荐先复用现有 v3 数据包. 原始消息已经保存在提交包的 metadata delta 内, 媒体为独立认证的资源记录. 浏览器索引只保存定位信息, 不再保存另一整份消息正文或媒体.

- 消息位置指向数据包及 metadata 中的记录序号, 并带稳定消息标识和修订标识. 打开页面时只解码相关包的 metadata, 从中取出所需消息. 单包 metadata 大小必须有上限, 超限旧包需要可识别的兼容路径.
- 时间目录保存 `(时间, 稳定标识, 正文位置)` 和子树计数. 用不可变树页支持按序翻页和按数量定位, 避免早期插入一条消息导致后续所有页重新编号和写入.
- 资源目录按对象标识保存包名, 范围, 解码长度和完整性信息. 文件版本目录保存块序列. 浏览器不扫描整个媒体包来找一个头像.
- 引用索引按会话和原始引用标识定位当前消息. 搜索索引按与桌面一致的文本归一化规则分块, 候选结果必须对正文再核对, 支持正反方向和稳定游标.

目录页, 搜索倒排块和文件块清单也合并存入少量不可变包, 不为每条消息或每个搜索词生成独立磁盘文件. 初始叶页目标 128-512 KiB, 扇出和缓存容量由实验确定, 不把这些初值当作性能结论. 浏览器使用有上限的内存缓存和 LRU, 不一次读入完整正文或索引.

新增目录确实占用空间, 搜索索引尤其可能较大. 需要分别统计目录, 搜索索引, 正文和媒体的逻辑大小与磁盘分配空间. 如果复用旧 metadata 导致随机读取过多, 再评估未来格式把消息变成可独立解码的正文块; 不为浏览器功能立即重写所有历史媒体.

## 快照与增量

目录生成复用当前查询索引, 读取已有消息的位置和最新修订, 不重新解析来源数据库. 首次为已有大归档补齐浏览器目录仍有全量遍历成本, 应明确显示总数, 已处理数, 阶段和速度, 支持暂停和继续.

后续更新仅处理新增或变化的消息及其索引页. 保留稳定的消息位置, 索引采用写时复制, 不在每次更新时重建全量索引. 倒排索引采用不可变段及有阈值的后台合并, 合并可中断, 旧快照继续可读.

浏览器目录必须与归档的已发布 HEAD 绑定. 小型物理入口文件只提供版本, 快照标识和根位置, 受保护归档不在此暴露会话名或搜索词. 发布方案需同时保留旧根和候选根: 先写完整包与认证根映射, 最后发布归档 HEAD. 读者选取与捕获 HEAD 匹配的根, 不混用两个快照. 崩溃, 整理, 备份和放弃任务都必须遵循同一规则. 原型中验证根映射的大小上限及回收流程, 再冻结磁盘协议.

浏览器读取期间固定一个快照. 发现新快照时提示可刷新, 不突然改变当前消息位置. 未完成的私有提交不可见. 老版本没有浏览器目录时应说明需要先生成, 不自动开始数小时的全量扫描.

## 密钥与解码

支持当前密码封套和直接密钥两种模式, 与桌面采用相同的测试向量. 封套解锁后派生各保护域密钥; 直接密钥输入 64 个十六进制字符. 目录, 倒排词项, 引用和资源清单与正文采用一致的保护状态, 不产生明文索引副本.

现有记录采用随机盐经 HMAC 派生记录密钥, 再以 AES-256-GCM 认证. 浏览器实现必须逐字节匹配当前布局, AAD, 归档标识和保护域, 不把它误当成简单的 nonce/ciphertext 文件. 修改密码仍只更新封套; 直接密钥不能通过改密码来替换.

Brotli 不能假定所有目标浏览器原生支持, 需要本地附带经过许可检查的解码实现并设解码大小上限. 在 Worker 中完成索引读取, 解码和搜索, 主线程仅渲染当前页面. 不持久保存密码, 直接密钥或解密后的搜索正文. 外观偏好可记忆; 无可用本地存储时使用会话内设置. 锁定时终止相关 Worker, 释放对象 URL 并丢弃明文缓存; JS 运行时不能保证所有秘密副本都被物理擦除, 不作此承诺.

## 媒体与安全

图片和短音频按需拼出当前对象并创建 Blob URL, 缓存受内存预算约束. 大视频先验证 MediaSource 或其他可分段播放路径. 某些容器或编解码器不能随机播放时显示限制, 不假装按需读取却把数 GiB 文件一次加载进内存. 可以由用户明确选择保存该单个文件后播放.

归档内容全部作为不可信数据处理. 不执行包中脚本, 不使用原始消息拼接可执行 HTML, 限制资源路径和解码长度, 验证认证标签及位置边界. 页面无网络依赖, 默认禁止外部图片和远程请求, 附件下载由用户发起. 测试损坏目录, 路径穿越, 解压炸弹, 错误密码, 截断包以及恶意消息正文.

## 分阶段落地与验收

1. 仅做可丢弃原型: `file://` 目录授权, v3 metadata 和资源解码, 两种密钥模式, 大视频边界. 失败时先报告限制再调整方案.
2. 建立版本化浏览器目录和快照协议, 先实现会话列表, 时间分页, 文本及图片, 与桌面逐项核对.
3. 加入索引搜索, 引用跳转, 身份历史, 媒体, 增量生成及断点. 通过故障注入后才接入正式 UI.
4. 验证浏览器完全离线运行和发布包许可, 文档明确支持矩阵及不支持项. 用户认可性能与空间结果后再决定新建默认值.

使用隔离合成样本覆盖 2 万, 100 万和 300 万条消息, 大量小资源, 单个大视频, 明文与两种加密模式. 在可用的固态盘和机械盘上分别记录冷启动与热启动, 首屏, 页跳转, 搜索首批, 小增量, 初次目录生成, 加解密吞吐, 峰值内存及实际分配空间. 不以暖缓存小样本推出所有硬盘的推荐值. 不能使桌面打开或更新强制等待浏览器目录整理.

验收底线: 不安装桌面程序即可离线打开; 不解包整份归档; 首屏不遍历全部历史消息; 小增量不重写全部浏览器索引; 正文和媒体不重复保存; 受保护归档没有明文索引泄漏; 中断后旧快照保持可读. 性能目标值待第一阶段实测建立基线, 不在此虚报数字.

## 已核对的官方资料

- [Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access): 目录句柄和用户授权的依据; 不构成对本项目 `file://` 场景的实测保证.
- [SQLite WASM persistent storage](https://sqlite.org/wasm/doc/tip/persistence.md): 浏览器数据库存储和 Worker/隔离条件的边界. 本方案不直接加载桌面加密查询库, 也不强制使用 OPFS.
